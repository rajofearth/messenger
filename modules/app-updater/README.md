# App updater

Android-only local Expo module. Public TypeScript entry point is `src/services/appUpdater.ts`. Rebuild the native app after adding the module. Expo's default local `modules/` discovery registers it; the *install* side needs the manifest bits generated by `plugins/withUpdateInstaller.js` and listed in `app.json`. Not supported in Expo Go, iOS, or web. Check `isAppUpdaterAvailable` before use on shared screens. Unsupported calls throw instead of reporting fake success.

The module downloads an APK release of this app and hands it to Android's package installer. It never installs silently, and it never decides *whether* an update exists: that is the release feed's job (`src/data/updateFeed.ts`, decided by the pure rules in `src/domain/updates.ts`).

## Parent API contract

| Function | Contract |
| --- | --- |
| `getStatus()` | Running app version and install readiness: `{ versionName, versionCode, canInstall, cachedBytes }`. `versionCode` is the authoritative "is an update still pending" signal. |
| `downloadApk(url, sha256)` | Downloads, verifies, and caches the APK. Resolves `{ path, bytes, reused }`. `reused: true` means an earlier download still matches the digest, so no network was used. |
| `cancelDownload()` | Stops the running download. Resolves `true` when one was cancelled, `false` when none was running. |
| `clearDownloads()` | Deletes the cached update packages. Rejects while a download is running. |
| `installApk(path)` | Hands a verified path to the package installer after checking the install permission. Resolves `{ started: true }`; the user still has to confirm. |
| `openInstallPermissionSettings()` | Opens the per-app "install unknown apps" screen (Android 8+) or Security settings (Android 7). |
| `openAppSettings()` | Opens the app's system settings page, for the "restricted settings" case. |
| `subscribeToProgress(listener)` | Live `onDownloadProgress` events, `{ downloadedBytes, totalBytes }`. `totalBytes` is `0` when the server did not declare a length. Returns `{ remove() }`. |

Failures reject with a stable `code`: `ERR_UPDATE_BUSY`, `ERR_UPDATE_HTTP`, `ERR_UPDATE_TOO_LARGE`, `ERR_UPDATE_CHECKSUM`, `ERR_UPDATE_STORAGE`, `ERR_UPDATE_CANCEL`, `ERR_UPDATE_MESSAGE` (a malformed feed), `ERR_UPDATE_PATH` (a path that is not a downloaded update), `ERR_UPDATE_PERMISSION` (the user has not allowed installs), and `ERR_UPDATE_INSTALLER` (no package installer answered). Codes are what the UI switches on; messages are for logs.

## Download behaviour

`downloadApk` runs on a single worker thread, one download at a time (`ERR_UPDATE_BUSY` otherwise). The file name is derived from the expected digest, never from the URL or the feed, so a hostile manifest cannot choose a path: the target is always `cacheDir/updates/update-<first 12 hex of the digest>.apk`. Before downloading, the directory is emptied, so at most one release APK is ever cached and a file whose digest no longer matches its name cannot survive. Downloads happen through a `.part` file that is renamed only after the streaming SHA-256 matches; every failure path deletes it, including an `Error`, a cancellation, a timeout, an HTTP error and a checksum mismatch.

Fragment cleanup does not depend on the user starting another download. Every status read with no download running deletes leftover `.part` files, so a process killed mid-download leaves nothing behind after the next launch. A verified APK is kept on purpose for a retry, and is deleted once the running version code is newer than the build that started the install; that comparison is local, so an offline launch after an update still clears the cache, and the completed attempt is cleared even when Android has already removed the cache directory, so a later download is not mistaken for residue from that install. Redirects are followed by hand (GitHub release assets redirect to a CDN), a maximum of five, and only to `http`/`https`. The declared and the actual sizes are both capped at 200 MiB. `http` is accepted only in a debuggable build, so a test feed can run on a laptop.

The digest proves the bytes match the published release. It does not prove the release is genuine; that guarantee comes from Android refusing to install an APK signed by a different key. Never disable that check by shipping a "signature ignored" install path.

## Permissions and platform boundaries

`REQUEST_INSTALL_PACKAGES` is declared in the app manifest by `plugins/withUpdateInstaller.js`, together with the `FileProvider` at `${applicationId}.fileprovider` and its `file_paths.xml`, which exposes only `cacheDir/updates`. `installApk` refuses any other path, and the provider cannot share anything else.

Android 8+ has a per-app "install unknown apps" switch: `canInstall` reads it, and the app must ask the user to turn it on, explaining that it is needed to install the update. Android 7 only has a global unknown-sources setting, so `canInstall` reports `true` and the installer guides the user. Some OEM builds hide the switch behind "Allow restricted settings" in the app's system settings; `openAppSettings()` is the fallback.

The module does not run in the background, does not check for updates on its own, and does not keep the process alive. It holds no wake lock and declares no foreground service, because the download only happens while the user is in the app.

## Validation

Focused Kotlin compilation: `gradlew.bat :app-updater:compileDebugKotlin --console=plain --max-workers=2` from `android/`, after `npm run android:prebuild`. TypeScript: `npm run typecheck`. Expo autolinking must list `app-updater` and `expo.modules.appupdater.AppUpdaterModule`.

Device acceptance checklist, not yet verified on hardware:

1. Clean install, check `getStatus().versionCode` against `app.json`.
2. Download a release APK, interrupt the network mid-download, confirm the `.part` file is gone and the retry starts over. Then kill the app mid-download, relaunch, and confirm the leftover `.part` is gone without starting a new download (`adb shell run-as <applicationId> ls cache/updates` in a debuggable build).
3. With installs still disallowed, `installApk` rejects with `ERR_UPDATE_PERMISSION`; the settings intent lands on the app's own toggle.
4. Install the downloaded package over the current build; confirm the app restarts on the new version and the cached file is cleared on the next launch, including while offline.
5. Rotate a published digest to a wrong value and confirm `ERR_UPDATE_CHECKSUM` with nothing installed.
